# Installed Node dependency acquisition

This candidate connects one fixed installed profile through the public source
owner, admission, Journal, native producer, retirement, Checkpoint, verifier and
result readers. It does not declare actual Linux execution or installed
qualification. Activation still requires the genuine selected signed npm/Node
and native capability closure; unsupported packages remain refused.

## Supported profile

The first profile is `npm-ci-v1`, npm 10.9.2, package-lock version 3, Linux x64
with the existing signed Node 24.21.0 and strong namespace boundary. It accepts
one root `package.json` and `package-lock.json`, frozen registered public HTTPS
dependency endpoints, and a complete integrity-bearing registry dependency
graph. Workspace/local/Git/alias/bundled layouts, nested package manifests or
lockfiles, pnpm/yarn, project `.npmrc` execution configuration, and private
registry credentials are refused before a Run or productive claim. Existing
credential unions/history are still checked; a public endpoint is represented
explicitly and never by a fabricated empty credential binding.

The original 1-MiB/10,000-entry JSON bounds remain. The public package/download
ceilings remain 50,000 packages / 5 GiB by default, at most 200,000 / 20 GiB;
they are ceilings, not a promise that every such graph fits the other original
resource limits. No profile or request is silently reduced to make it fit.

## One signed asset and one lifecycle

`npm_package_data@10.9.2` is a non-executable `bundle_object` inside the existing
signed RuntimeBundle v1. Its fixed data image retains the all-and-only regular
files from the official `npm-10.9.2.tgz`, after both pinned SHA-256 and SHA-512
checks. The upstream archive has 2,408 files / 11,745,533 source bytes. The
image has 11,950,276 bytes; its actual conservative file/directory page bound
is 20,463,616 bytes. These are source/component observations, not Linux READY
qualification. No source file becomes an individual CAS object.

The fixed image format bounds all paths, records, file bytes, full digests and
exact EOF. Only the dependency recipe may materialize at most 4,096 files and
32 MiB into its original volatile, private runtime root. Every file is opened
without following links, hashed completely, made read-only, and joined before
READY. No thousands of durable per-file namespace/fsync operations are added.
The original tool/source/verifier 32-file asset guards are unchanged.

The dependency operation reuses the existing Run, WorkerLaunch, generation,
controller scope, Journal, dispatch fence, lease and physical retirement. It
does not introduce a runner, resource ledger, host npm or ambient shell. A
fixed guest npm entry invokes the actual retained upstream CLI through the
signed Node; any wrapper is identified as a wrapper, not as upstream bytes.

## State and execution ordering

1. Source capture validates the root layout and all original package/lock
   bytes. Admission resolves the exact public registry tuples and freezes the
   `DependencyPolicy`. `allowInstallScripts=false` is the default. When true,
   only the exact original dependency-script authorization may be consumed
   into the immutable RFC template in the same admission transaction.
2. Every candidate derives a fresh plan from its own complete SourceManifest,
   package bytes and frozen policy. Its verify frontier starts in
   `dependencies`, with the matching plan ref. Changed candidates cannot reuse
   an old plan or script ordinal.
3. One `builtin:dependency-acquire`, `opKind=tool`,
   `workspace-rollback-retry` operation reserves one tool call. Its immutable
   request, grant, same-owner release and permanent claim bind the complete
   plan. The new native transport variant is fixed integrity-GET against this
   batch's registered targets; it is not a caller URL fetch API. Only the
   original bounded integrity-GET retry exception applies.
4. The broker retains full status, transfer count, integrity and actual
   close/join observations. Complete matching package bytes enter CAS; partial
   downloads remain unreferenced and never become cache authority. The cache
   manifest contains exactly the required package tuples and contiguous
   attempts, with complete-byte CAS refs and the original SRI domain separate.
5. The same registered invocation materializes only those verified inputs and
   runs real npm ci offline. Candidate source and existing Git metadata are
   read-only; only fixed dependency/cache/temp roots are writable. The runtime
   has no broker credential, ambient config, host file descriptor or network.
   Scripts run only under the exact original template/grant and candidate
   ordinal, with the same no-egress containment.
6. Before readiness, all npm descendants are dead, every producer/reader and
   FD has joined, and the original full candidate projection is rehashed.
   A complete protected-M rehash that proves drift records its own integrity
   evidence and failed sealed Checkpoint, followed by the kernel-integrity
   Stop. This is not a fabricated successful Ready or a worker-recovery
   quarantine row. A caught error, access denial or timeout never becomes
   audited source-write, death or drift evidence. Unverifiable data retain the
   original result/fence and require recovery.
7. One transaction commits the completed acquisition Journal fact, exact
   cache/ready item, post-effect ready Checkpoint, budget settlement and
   `verifiers` frontier. The ready item's `installedTreeDigest` is the closed
   `cliq-node-managed-tree-v1` digest of the exact `node_modules` subtree in
   that same Checkpoint's complete workspace entries. The full M, original
   source/projection, private Git, snapshot and parent death remain separate
   mandatory original proofs; the managed digest never substitutes for them. The ordinary required verifier and
   sole final-result transaction independently rewalk the dependency closure.

Cancellation, expiry, storage failure and UNKNOWN retain the same invocation,
original fence and physical retirement requirements. A no-process acquisition
failure records the actual joined broker traffic, unchanged complete M and
real parent retirement without inventing a npm result. An uncertain process
keeps its original fully charged UNKNOWN. Its stopped terminal worker-recovery quarantine
requires the original continuously held native broker mutex plus all I/O joins,
or a successor's independently proven death of that exact claiming Supervisor
process. Parent/controller death alone cannot fence a same-Supervisor broker. No request is
reissued because a connection closed, a pathname matches, or a timeout fired.
Installation's 30 seconds, READY's 5 seconds, Stop's 2 seconds, original
scanners, full reads, byte limits and all-issued joins remain unchanged.

## Actual qualification still required

The installed entry must demonstrate a real integrity-locked package, offline
build/test, post-effect ready Checkpoint, required verifier, reconnect/restart,
original-response replay, exact script allow/deny, tampered archive rejection,
storage failure, cancellation during both materialization and running npm,
and complete physical recovery. Pure lock/image tests do not qualify these
cuts. Private registries, pnpm/yarn, other ecosystems and their real provider
credentials remain explicitly unsupported by this first profile.

## Fixed execution and immutable reuse boundaries

The worktree and any existing private Git data stay read-only. Only
`node_modules`, private cache, HOME and TMP are writable and remain NOEXEC. The
fixed signed `/bin/bash` is npm's script shell; repo `.npmrc`, ambient
`NODE_OPTIONS`, user/global config and inherited registry/proxy settings cannot
select another shell or extend network authority. Default deny really passes
`--ignore-scripts=true`, including when root/dependency lifecycles exist.
Explicit script consent binds the complete ordinary and ignored program input,
root package/lock/gyp, signed Node/adapter/image, registry and environment.
Generated outputs outside `node_modules` are unsupported by this first profile.

Relative `.bin` symlinks use the existing typed no-follow snapshot and restore
implementation. Node can interpret authorized JS data. Direct execution of a
workspace `.bin` script remains subject to NOEXEC and the fixed signed ELF
allowlist; no shim, executable remount or host command fallback is provided.
General npm command/native-addon compatibility is not claimed.

A child inherits only immutable data from a genuinely sealed parent Ready at
its original allocation Checkpoint. It independently materializes and verifies
its generation and seals its own candidate. No child GET/script Journal, script
grant or attempt is fabricated. Ignore-scripts equality covers all actual
package/lock/gyp/platform/Node/npm/registry/environment inputs, while both full
source graphs are still read and original refs retained. Scripts-enabled reuse
requires the complete program/source condition as well. A derived fork source
is explicitly data, never the original capture ref, and historical reads do
not publish missing CAS objects. Drift remains unsupported/waiting.

An identical-source Delivery may use only `inherited_verification` in the
verification closure, bound to the same original source result, full source
closure, immutable verification provenance and dependency plan. It creates no
local Ready, GET, installed M or script permission. Nonidentical Delivery takes
its own dependency lifecycle; the source Run's script template cannot authorize
it. Its own genuine approval can derive a Delivery-owned exact-source template.

## Executable validation entry points

The existing installed verifier journey accepts the trusted qualifier-only
`--locked-node <official-npm-archive>` suffix. It validates the entire pinned
archive before building the signed package, runs the unchanged original ten
cases and original scanner first, then adds three public locked root Runs,
one genuinely delegated child and an identical-source Delivery. The original
24 model POSTs plus eight new model POSTs total 32; four registered package
GETs are separate actual calls. Both kinds stay in the same cumulative corpus
and scanner budget. The child reuses its original sealed parent Ready with
zero child GETs; after its edit/await/merge the parent installs its own new
candidate. One real package is larger than 1 MiB; both
default ignore and exact root/dependency lifecycle paths use real upstream npm
and required Node tests. All original stream/count/byte/corpus limits and
finally joins remain. The new report profile needs its own strict consumer; it
is not silently accepted as the older report contract.

The existing free Linux verifier job acquires only the fixed official npm
source, refuses redirects or bytes beyond the original archive bound, and
checks both digests and the complete image before publishing its exclusive
no-follow input file. This build-time source download is not a runtime GET
claim or qualification. The same root harness accepts the archive only for
the fixed verifier campaign, without a new driver, ledger or execution grant:

```sh
sudo bash scripts/kernel/qualify-systemd-user.sh --run-verifier-journey \
  --locked-node /absolute/npm-10.9.2.tgz /absolute/node /absolute/new-output
```

Focused native commands are `scripts/kernel/testing/dependency-native-family.test.ts`,
`dependency-broker-lifecycle.test.ts` and `dependency-npm-stage.test.ts`, run via
the supported Node test/tsx entry. They compile and exercise the production
Linux family and original namespace/FD/cap/NOEXEC boundaries where supported.
The local official-npm program regression is separately labeled host mechanism;
it cannot supply Linux birth, READY, grant, CG, Stop or installed proof.

A successor interrupted after the permanent claim but before UNKNOWN may only
record a fully charged negative fact after the original StateOwner process
death is independently proven from the complete same-root owner history and
a fresh OS observation. It records no guessed transfer counters, npm output
or readiness. The original child domain still needs its separate genuine
worker recovery and complete retirement before terminal abandonment.

Protected-workspace failure uses the separate closed
`cliq-dependency-integrity-evidence-v1` data. It names the original claim and
capture, real before/after M refs, both unchanged-or-changed original projected
source refs, original generation, inspector, exact changed protected-entry
digests and any real private-Git refs. The full retirement reader reproduces
those relations before its Stop cause can reference it. A retirement receipt
is not relabeled as a general integrity observation. In particular, an ignored
program drift is not represented by a fabricated changed SourceManifest.
