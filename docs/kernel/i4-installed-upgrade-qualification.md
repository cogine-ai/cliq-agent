The independent `installed-runtime-upgrade` hosted job exercises an actual old
product install, two ordinary unverified edit Runs and the formal signed upgrade
entry. It complements the unchanged main26 scenarios. It does not replace their
secret corpus, qualify an official release, switch the default CLI, or establish
complete I4 support. Linux execution is pending until an actual job reports the
complete closed profile below.

## Real operation and recovery

The driver reuses the original disposable UID, owned bounded ext4 HOME, immutable
root ledger, systemd user manager, Secret Service and original cleanup framework.
There is one ordinary production scheduler. The old installer and old public
client are compiled from actual old source. The target client is compiled from
the current product source. No old database, StateOwner, Run, grant or death
receipt is manufactured.

The old product receives explicit endpoint registration, Secret Service enrollment,
workspace Trust and ordinary per-action permission. Its actual HTTPS model fixture
requests one private edit and finishes. The public terminal recovery read, complete
result/diff/source bytes, exact charged Journal and normal retained worker seals
must validate; the recorded worker PID/start lifetimes must actually be absent.
The host source remains unchanged. This is `completed_unverified`, with explicit
`allowUnverified:true` and an empty verifier set.

The target signed SEA is invoked only as:

```text
targetPackage/supervisor --upgrade-runtime StateRoot targetPackage
```

Release roots come only from that SEA's embedded asset. The campaign cannot
inject roots through this public command's arguments or environment and does not
manually guess low-level stage/kill/selector order. The producer must perform its
real stage, original unit Stop, original process lifetime death, sole migration
transaction, registered receipt recovery, selector publication and target READY.
The old Supervisor and keeper lifetimes are independently checked absent.

After target HELLO, the first old submit response, original terminal response,
result bytes and every original CAS file's bytes and inode metadata must remain
equal. Old endpoint and credential records remain readable. An actual new submit
using the old runtime-bound endpoint/credential must be refused without a new
Run or model POST. Target8 then receives explicit new public registration and
enrollment, and completes its own actual private edit Run. The old credential
can be explicitly revoked. Calling the same upgrade entry again must return the
same registered receipt and preserve the old first response; it cannot reapply
DDL or rebind an old credential.

Both final units must really stop within the original2s bound. The owned keyring,
HTTPS connections, clients and all original child pipes join before the retained
corpus is scanned. The new explicit scope has one scanner across both Runs,
all commands, report and complete kernel/authority/CAS corpus:4096 independent

no independent values are merged/deduplicated, and no counters reset. Original
READY5s, request30s, enrollment60s and terminal90s limits remain unchanged.

## Closed report and gaps

The report format is `cliq-installed-runtime-upgrade-qualification-v1`, profile
`actual_2513_schema7_to_signed8_edit_run_v1`. Success requires exactly two ordered
schema7/schema8 cases, four HTTPS POST/TCP/TLS lifetimes, one charged edit in each
case, complete distinct result/retirement references, original-byte preservation,
actual old-runtime authorization refusal, explicit new authorization, same-receipt
recovery and every resource/scanner join. `installed-upgrade-result.ts` strictly
validates complete and partial data; unknown profiles, missing cases, missing
death/join flags, extra fields, changed caps or success after an error are rejected.
Pure decoder tests are metadata tests, not Linux or execution authority.
If the one corpus exhausts its original budget, the fixed original scanner
failure code, before-corpus counters and closed source bucket are retained;
the failed scan is not reset, split, silently resumed or called qualified.

The report always keeps `officialReleaseQualified:false` and
`wholeI4Qualified:false`. This edit-only scope does not qualify required verifiers,
dependency acquisition, mutable Git metadata, arbitrary large installed history,
physical child parallelism or every crash boundary. Its successful small-state
upgrade consumes the final paged production retirement profile, not a former
small-object recipe.

The current positive fixture does not deliberately produce a genuine old43-character
source-error receipt: `legacy43ErrorReceipt.kind` remains `not_exercised`. An actual
old error's observed code determines its meaning; an intended symlink failure is
not assumed to be INTERNAL. Such receipts are never rewritten into UUIDs. If the
registered original retirement/error graph cannot be read under the exact upgrade
contract, production must refuse and preserve the original bytes. This historical
gap remains explicit; neither a pure fixture nor this positive profile upgrades it
to a verified installed case. Official maintainers still supply compiled release
roots, a real release signature and the complete release/upgrade qualification.
