# Current migration inspection

An original producer and a current checker have different lifetimes. The
original online archive is created, fully copied, audited, sealed and closed.
Its completed same-process result is issued only after that actual close; a
copied record, schema label or caller callback cannot enter that issuer branch.
Restoring recovery reads the separate complete persisted producer witness and
observes the same original objects through a genuinely newer Owner.

The current inspector uses a distinct native tag. It cannot receive any of the
original creator's 25 mutation/candidate methods. It holds the same original
StateOwner, selected native image and global EX. It opens only fixed existing
objects: the original Legacy root and backup, current fixed documents, and the
original migration/kernel-archives/<archiveId> collection member. It creates
no backup, candidate, archive, ledger or execution permission.

Retained import history closes every original control predecessor,
preparation, authenticated channel, original Owner history, source credential
observation, inventory, candidate, signed schema, receipt and committed SQL
response. In rollback_draining, the strict EX reader follows the exact
retained original control and Kernel authority references. It also rereads the
actual current fixed documents and original SQL cut. Ordinary SH startup
continues to report this phase as recovery required.

The current native observer independently checks the recorded actual source
and backup identities, complete bytes and complete directory sets. It retains
the original canonical Legacy locks through this observation. An absent
auth.json is an observed fact, and does not substitute for the original marker
required in rollback_draining.

The original archive manifest selector includes its original collection,
directory and file identities, full byte count and SHA-256. It contains no
caller path. Native first verifies the complete readonly manifest through an
actual owned reader, including EOF, fsync and close. A new reader then supplies
bounded chunks to the strict canonical header decoder. Only after that decoder
finishes may the current image/CAS identities be selected.

The complete archived SQLite image is hashed against the already audited
original producer image; no new SQLite pager is opened and this step is not a
claim that a second integrity check ran. A second complete manifest consumer
supplies bounded entries. Each archived CAS object must match its original
archive inode, size, full hash, readonly mode and single-link identity. Native
then scans all and only the physical archived namespace and the fixed archive
root. The original live CAS directory identity is checked, while post-capture
audit objects are not misrepresented as members of that old snapshot.

When the original manifest captured the model store, the inspector borrows a
genuine existing-source model visitor under the same EX. It validates the
original readonly binary inventory, every source and archived file's identity
and complete bytes, and final all-and-only censuses. A successful census closes
the original visitor and all active readers. The inspector retains the readonly
target directory and inventory guards until it closes. The rollback conductor
must keep the original model lock through marker publication.

Each byte step is at most 64 KiB and each enumeration step at most 64 entries.
Original source/backup and archived namespace indexes share the existing
256 MiB native metadata budget; the bounded JS header and current chunk are
additional explicit allocations. There is no million-entry JS vector. The
original 50 GiB archive payload bound includes SQLite, CAS, model data and
inventory, and the manifest.
The observer preserves all original time limits. Real filesystem latency,
maximum fixture behavior and Stop2 remain physical qualification requirements.

Data corruption stops further observations. It does not pretend that genuine
owned descriptors failed to close: the original lock task must still join and
the exact current receiver must actually consume its handles. A failed real
join/close retains the original scope and poisons retirement as before.

The fixed rollback publisher is separate from this readonly receiver. It
borrows the same account EX, model scope and canonical Legacy locks. The
original archive temporarily borrows the same model visitor and returns it
after actual close. The credential scope retains its native guard without a
write pager. The current source-absence profile removes only the exact
original migrated auth marker and verifies the whole restored tree.

The migration tail keeps the authenticated request, original Kernel marker,
draining control, compact archive witness, auth absence, Legacy generation,
receipt and prepared restoring records outside productive CAS. The restoring
control binds both actual staged Legacy-authority file identities and both
displaced Kernel-marker identities. The Store roots the exact tail records and
gracefully releases the Owner in its last real SQLite transaction. Only its
actual committed and closed-driver receipt enables native authority writes.
The native publisher exchanges and syncs the Legacy copy first and the Root
copy last, then only retires resources.

A complete archive and the actual original auth-marker inode are durably
bound in the archive-ready control before the first auth unlink. A successor
verifies the exact original archive and a real predecessor lifetime
retirement. It can remove the same still-present marker or independently
observe and sync the original intended absence. Its absence observation
carries its own Owner and does not claim the predecessor's unlink.

A restoring successor requires the exact preparer and acquisition history.
The original final SQL cut must be wholly present under a graceful release
or wholly absent. The absent branch requires both authority copies still
unpublished. It checks the same original archive and unchanged
productive SQL families. For local-service witnesses it rechecks the complete
pack and original source bytes, then independently proves each retired launch
under its own exclusive read scope and the actual installed Anchor. The
original stage identities distinguish a pending
Legacy exchange from the same already-published original object. A successor
joins the same canonical lock order, completes its own last release and
publishes only the missing prepared authority. Durable Root Legacy authority
stops Kernel acquisition. Earlier interruption without a durable complete
archive-ready record, missing birth identities for partially staged markers,
unknown namespace members, linked residue and unproven runtime witness state
still require recovery.
These branches require independent installed and crash qualification. Typed
GC remains delete-zero until every retained parent/purpose and the complete
physical namespace are closed.

The Linux migration producer observes same-UID process lifetimes and every
available descriptor from its original procfs and held Legacy directory.
Only the exact held Kernel directory is excluded when it is inside Legacy.
The cursor checks the actual executable and command line, and resolves
recognized file-backed launchers to the actual entry and package bytes,
including the declared version and exact digests. Unresolved package-manager
launches, other mount namespaces, aliased source mounts, hidden process
enumeration, unknown images and inaccessible descriptors refuse the cut.
The limited supported image and package profile still requires a positive
installed qualification on the actual target environment.

An early refusal closes its process cursor and verifies that Root control,
Root authority and the original Legacy rendezvous are still absent before
the Store can reopen ordinary shared service. After the original control
exists, the producer rechecks the same process cut under the original Legacy
locks and again immediately before publication. The model store's genuine
exclusive scope precedes Legacy locks and remains held until their actual
retirement. The credential scope remains held through the final import
publication. No process arguments or environment bytes enter receipts or logs.
