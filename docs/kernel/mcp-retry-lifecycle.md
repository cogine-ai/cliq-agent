# MCP retry and terminal ownership

The installed client already accepts exact per-tool retry risk consent and a
signed reconciliation profile selector through `mcp register --recovery-json`.
That v1 request creates neither an effect grant nor a native release. Missing
consent, an unsupported transport/profile or an incomplete implementation
continues to refuse before execution. The current production recovery gate
remains manual while the owning retry/reconciliation composition and real
installed qualification are completed.

Every retry keeps the original operation, frozen input, stable call key,
registry and tool contract. A productive claim is a new contiguous Journal
attempt and reservation. The original claimed UNKNOWN and its whole-once
settlement remain unchanged. The literal three-dispatch capacity and
500/2000 ms backoffs are read from the full original history; no transport or
SDK performs a hidden resend. The native deadline first bound to the original
call survives new grants, worker restoration, replacement preparation and
Supervisor succession. A first native claim records the full actual HTTP
binding or the original stdio launch preparation; absence of those records
cannot be filled with a new deadline.

`cliq-mcp-retry-dispatch-closure-v1` closes only the old local dispatch. Its
complete closed fields bind the original prepared/claim/UNKNOWN sequences,
request, target, grant, registry, token, once-settled budget, original claiming
owner and current inspector. It either retains the same original irreversible
native join/revocation with zero active releases, or names genuine death of
the original nontransferable native creator process under a strictly newer
StateOwner. The latter branch reobserves that original PID/start lifetime
before the actual transaction time sample. Original owner/root/installation,
history, full native lifecycle, physical worker retirement, five-second
freshness and final SQL cut checks remain mandatory. A socket close, elapsed
lease or matching content does not create this evidence.

The opaque original admission owns a new preparation. A structural evidence
pair or validation callback cannot mint it. Its original physical receiver
leaves only after the new preparation actually commits the same closure.
Previous preparation evidence never leaks into the new effect claim: that
claim owns a new exact transport identity and permanent fence.

For a still-unused final UNKNOWN, the existing terminal finalization entry
stages its fixed `RetryUnknownCancelledResult`, runtime failure evidence,
StopIntent, terminal detail, ordered batch closure and Session outcome in the
one terminal transaction. The result says exactly that the Run stopped without
using the ambiguous result. It does not assert failure, absence or cancellation
of the remote effect. The original Journal and budget settlement are neither
refunded nor charged again. Earlier retry UNKNOWNs retain their identical
already-committed closure; a still-last UNKNOWN needs the genuine current
physical closure. Cleanup acknowledgement follows the actual terminal commit.

The original stdio launch capacity is independent of the productive retry
ceiling. Its default remains two. Two actually claimed and fully retired
initialized servers can exhaust that capacity before a third productive
attempt is permitted. That outcome uses the fixed runtime/resource cause
`mcp_call_resource_exhausted` with `resource=server_launch_capacity` and the
original `used`/`limit`, plus the same unused-result carrier and terminal writer.
It creates no third worker, server or effect preparation, cannot reset the
server charge, and does not claim that three productive attempts occurred.

The shared model-broker terminal reader accepts a first Stop staged by that
same original branded finalization only after its full original cut matches.
It still requires the original model token/producer and strictly newer real
creator-process death. A same-process model UNKNOWN continues to wait; the MCP
finalization brand supplies no model fencing authority.

These data and source regressions do not establish installed retry, signed
status inspection, cancellation, restart or Stop2 qualification. The public
gate must remain closed until each production writer and historical reader,
purpose-specific retention edge and corresponding real Linux campaign passes.
