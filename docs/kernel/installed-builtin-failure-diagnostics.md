# Installed builtin failure stages

The signed installed failure observer reuses its existing scheduler failure
envelope for closed builtin work labels. They distinguish preparation and the
permanent claim, complete claim/launch-closure reads, original native parent and
recipe, guest/script identities, sealed inputs, real construction/READY/process
observations, release, result and capture. The original revoke/history/evidence
and UNKNOWN settlement branches remain in the same order.

An original failure keeps its original stage after successful independent
cleanup. A cleanup failure retains the actual cleanup stage and the unchanged
retirement refusal. Labels and callback errors grant no birth, release, result,
death, retry or settlement authority. Unsubscribed images install no observer;
phase handling performs no I/O or clock sample. Errors remain unchanged and the
existing observer reads only its fixed error class/code descriptors.
The same closed scheduler vocabulary includes the original recovery `cut`
and `preparation` boundaries added by the complete upgrade audit, preserving
their `result_recovery_*` projection without changing recovery itself.

completed or UNKNOWN entry after the first `drive_agent/ARTIFACT_MISMATCH`.
Its retained JSON does not identify a particular failed assertion. These stage
labels preserve that failure and do not qualify the native invocation, its
retirement, the final source result or Delivery publication. The original
