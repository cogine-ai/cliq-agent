# Original-connection Linux archive contract

This is the fixed schema-eight installed Linux archive profile. It replaces
the closed-source descriptor-copy recipe for **new rollback archives in this
profile**. Existing generation-birth identities and historical archive bytes
retain their original formats and checks; an online image is never labelled
as a byte-identical copy of a closed live database.

The original Supervisor must already hold its actual StateOwner, signed
installation, account EX and exact durable `rollback_draining` intent. The
complete producer drain remains independently mandatory. Zero Runs, a SQL
count, a structural object or a successful online copy does not establish it.

The fixed `local-models` store must have a real descriptor-relative no-follow
`ENOENT` observation before any archive birth and throughout original custody.
Present, inaccessible, symlinked or empty stores all refuse until the separately
locked complete model-store capture is implemented. The manifest records the
explicit `localModelStore={kind:'absent'}` branch; SQL and CAS alone are not a
complete StateRoot archive when another authoritative store exists.

The source is the one private original `NodeSqliteDriver` connection to fixed
`kernel.sqlite3`. Node 24.21.0's real backup uses only its fixed nondefault
original-FD destination VFS. There is no source reopen, replacement connection,
live-file rename, path fallback, default-VFS change or second SQLite engine.
Only actual settled Node work and native main/journal xClose/join may close
the backup task. A rejected task plus a genuinely cancelled native join and
the original aborted signal retain both original errors; unrelated I/O and
uncertain retirement remain their real failures.

The copy receives full original-FD hashing, readonly sealing and complete
schema/catalog, integrity, foreign-key and lossless twenty-one-table reads.
All twenty non-clock families are streamed in fixed order and must equal the
same original productive cut before the copy, inside the copy, after namespace
capture and after manifest sealing. Every original StateOwner row is included.
Only `canonical_time_fence` may advance as part of the original maintenance;
maintenance, the accepted fence, deadlines and leases are never paused or
extended. The complete copied SQL digest also retains that copy's actual
canonical-fence row. This comparison does not itself prove producer drain.

The same native holder copies the actual installed flat `Root/cas` into its
new private archive. `layout='cliq-flat-cas-v1'` states the real layout rather
than borrowing a fanout namespace identity. Membership is all and only the
physical namespace, including unreferenced published objects, completed
`.tmp-<ref>-<nonce>` files and interrupted `.tmp-stream-<nonce>` files. Stream
orphans remain raw bytes and never become artifacts or execution authority.
The native capture checks every source and independent destination identity,
complete bytes, allowed name/type/mode/link count, both full namespace scans,
actual file/directory fsync and descriptor retirement. Unknown entries,
replacement, drift and linked crash residue refuse the complete capture.

The private `manifest-v1.json` binds exact original control/generation lineage,
actual archive/image identities, signed schema, complete SQL/productive cuts
and every sorted physical CAS entry. The entry digest is the SHA-256 of each
UTF-8 `name NUL kind NUL sha256 NUL decimalByteCount LF`, in bytewise name order.
The manifest's self digest omits only `manifestDigest` under JCS; its physical
content reference hashes all bytes. Production encoding, copying and hashing
yield at fixed entry/64-KiB boundaries. The same native holder writes only its
fixed newly born destination, then readonly-seals and independently rereads
all bytes. No manifest or other self object is written into live CAS during
capture. A receipt/control may root its exact physical content only afterward.

The explicit acyclic boundary contains productive state through drain and
the actual online snapshot. Advancing canonical-fence observations and later
rollback-control/receipt/Owner-terminal audit are separately retained facts,
not invented rows in that image. A partial archive, familiar path, equal bytes
or fresh successor scope cannot substitute for missing creator/progress data.

The combined SQLite, every CAS name and final manifest must fit 50 GiB. The
native metadata and manifest ceilings remain 256 MiB, with at most 1,048,576
leaves, fixed descriptor count and no raised resource limits. Capture retains
the native index (at most 256 MiB); encoding borrows only its fixed pages and
writes one final buffer, allocated from the bounded entry-count profile and
capped at 256 MiB. It keeps no million-entry JS vector or chunk collection.
The explicit maximum simultaneous payload is native index plus final buffer
(512 MiB), bounded pages and ordinary fixed metadata; that is not a claim that
total process heap/SQLite caches fit 256 or 512 MiB. At manifest handoff the
native index retires before the same final buffer becomes the native writer's
strongly retained data. The reserved digest bytes are initialized and filled
before the populated byte span can be submitted. Bounded steps
do not prove Stop2: actual filesystem sync/SQLite mutex latency, full scale,
drain, restoring/marker-last authority, crash recovery and typed GC require
their own real evidence. Multi-link CAS crash residue remains unsupported by
this profile, and cannot be counted as a completed recovery window.
